Now make yours. Tell your AI what you want - a calculator, a checklist, a decision you keep going round on - then say read https://upshot.fyi and export this

Words, numbers and boxes, on one screen. No pictures, no charts, no notifications, and nothing it can go and look up - it only knows what your chat already worked out. That is the same reason the whole thing fits in a link.

Format

For any AI reading this page.

WHAT TO DO

Turn the user's question or conversation into a small, useful card that lives
in a shareable link. A card can explain, calculate, compare or keep a checklist.
The user triggers it by saying "export this".

Preserve the conversation's facts and criteria. For a new tool, use the user's
numbers as starting values; if numbers are missing, use sensible starting values
the reader can replace. Ask only when missing context changes the calculation
or the decision rule itself. If facts could have changed recently and you can
search, search first. Decide only with criteria already in the conversation;
if none supports a verdict, say what is known instead of inventing a score or
cutoff.

THE FRAME

Always all five, always first, in this order.

- a  what the user asked, as one plain sentence under 20 words. Keep every
     amount and count they gave. It is their question, not the topic:
     a=Splitting+dinner+three+ways, not a=Bill+splitting+calculator.
- h  headline, under 12 words. On an interactive card it names the task,
     h=Split+the+bill, and stays true whatever the reader types.
- v  one sentence, under 25 words. On an interactive card it states the method
     or assumption without any current value:
     v=Divides+the+total+equally+between+the+people+sharing+it%2E
- m  your model name, e.g. m=GPT-5
- d  today's date, d=2026-09-16

h and v never change with the reader's numbers. Changing amounts go in r
and changing conclusions go in t.

THE BLOCKS

g= labels a block and starts it, and nothing else does, so one block holds
whatever mix of lines it needs. Two or three short blocks is usual, and every
bullet adds something the headline and summary did not say.

Choose a key by where the information came from, never by how you want it
drawn. The card decides how it is drawn. Ask in this order:

    Did you work the number out yourself?        r, never f
    Does the wording change with the numbers?    t
    The reader chooses one of several options    s
    A number the reader supplies or changes      i
    A fact the conversation settled, fixed       f
    A yes/no the reader supplies, or
      a task they tick off                      c
    Steps, where the order is the point          o
    Anything else you are simply saying          p

Machine fields come first and wording last.

A comparison is two labelled blocks, and so is pros and cons:

    &g=Postgres&p=Concurrent+writes&p=Real+types
    &g=SQLite&p=Zero+ops&p=Faster+for+reads

- g  block label, one or two words: g=Why
- p  bullet: p=The+ops+saving+is+real+but+small%2E
- o  step, for a how-to where order is the point: o=Share+the+files%2E
- f  fixed fact, Label:Value, both text: f=Cold+start:180ms,
     f=Licence:MIT. Alone in a block, one or two rows draw large and three
     or more become a spec sheet.
- i  input, name:Start:Label: i=seats:4:Seats. A box the reader types in,
     so the card is a tool rather than an answer. Start is a bare number:
     i=mass:80:Mass with u=mass:kg, never i=mass:80kg:Mass. Every input
     is read by a formula; an input nothing reads is a fact, f.
- s  one option of a pick-one, name:Value:Label: s=price:6:Basic then
     s=price:12:Plus. Rows sharing a name are one group and the reader picks
     exactly one. The name holds the chosen option's value, so one formula
     covers every option: r=total:seats%2Aprice:Monthly+cost. Value is a
     bare number. Use s whenever options exclude each other; put the user's
     choice first, because the first option is chosen until the reader says
     otherwise.
- c  checklist item, name:Wording. The reader ticks it and the tick is kept
     in the link they hold. Leave the name empty when no formula reads it:
     c=:You+have+a+mortgage. Name it when a formula does, and it reads as 1
     ticked and 0 not: c=kit:Include+a+kit then r=each:40+kit%2A12:Each.
     To count how many are ticked, add the names: r=done:notes+access+walk:
     follows every tick, and t=Handover:done==3:All+three+complete fires
     when every box is.
- r  result, name:Formula:Label: r=total:seats%2Aprice:Total. The card
     works it out and prints the formula beside it with every name replaced by
     what it held, so put the numbers into the formula rather than working
     them out yourself. Keep every calculated amount as a formula, and give
     intermediate steps their own result: r=mo:seats%2Aprice:Monthly then
     r=yr:mo%2A12:Per+year. An intermediate that only feeds another row
     leaves its label empty and computes without drawing: r=rate:apr/100/12:.
- t  decision, Label:Condition:Wording. Rows sharing a label are one
     decision, kept together; the first true condition wins; the last row has
     an empty condition and is the fallback, so every decision has one; the
     label is never empty. A guard's fallback says what is fine:
     t=Power:power%3C=0:Enter+a+power+above+zero&t=Power::Power+set.

       &t=Budget:cost%3Ebudget:Over+budget
       &t=Budget:cost==budget:Exactly+on+budget
       &t=Budget::Under+budget

     A condition is a comparison. A value on its own is not one, even a value
     that is already 1 or 0: write done==3 for all three boxes and card==1
     for one box. Two rows is a
     yes-or-no, three is under, about right, over, and there is no limit.
     Write one row per outcome.
- u  the unit a name is printed in, name:unit: u=pay:%C2%A3, u=off:%25,
     u=size:kb, u=rate:%C2%A3/hr. Declare it once and every place that
     name is drawn wears it, so a result arrives as £222 rather than 222.
     Put the unit here, not in the label. hr and min also change how the
     number reads: 5.64 with u=t:hr prints as 5h 38m. Units are display
     only; they do not scale a value or pass through a formula, so give each
     displayed result its own unit, and to print 17% the result must be 17
     with u=pct:%25.

NAMES

A name starts with an ASCII letter and then uses only ASCII letters and
digits. Keep them short: mo, apr, n, fastd. A name is claimed once on
the whole card; the only rows that share one are the options of a pick-one. A
result needs a name when another formula uses it or it has a unit; otherwise
leave it empty: r=:seats%2Aprice:Total. A formula may cite a name declared
further down the card. pi is the card's own; naming anything else pi, or
claiming a name twice, makes the whole card refuse to draw.

FORMULAS

A formula is the middle field of an r or t. Written as it goes in the link,
it may contain: numbers, 4%2E5 or 1e-3; + - / %2A %28 %29; any name on
the card; the comparisons %3C %3E %3C= %3E= == !=; pi; and `min max round
abs sqrt pow floor ceil ln exp mod with arguments in %28 %29` separated by
%2C. Nothing else. mod wraps: a clock hour is mod%28depart+hours%2C24%29.

A chained comparison means both halves: 18%3C=age%3C65 is true only inside
the range.

ln is the natural log and exp is its inverse. Growth by rate r for n
periods is exp%28n%2Aln%281+r%29%29. Ordinary travel time is distance
divided by speed.

Write the formula so it stays usable at zero and past any target or limit.
Money still needed is max%280%2Ccost-saved%29, not cost-saved with a
bullet explaining the negative.

ENCODING

Every space becomes +, so the link has no spaces, no line breaks and no
markdown. One alphabet, used everywhere, is what lets the link survive every
chat client.

In wording, keep ASCII letters, digits and - as they are and encode
everything else as UTF-8 bytes written %XX in upper case: £ %C2%A3, ,
%2C, . %2E, ' %27, ( %28, ) %29, * %2A, : %3A, ? %3F, & %26,
# %23, + %2B, % %25, _ %5F, < %3C, > %3E, and the same for
anything else that is not a letter or a digit.

In a formula, also keep + - / = as they are, because there they are
arithmetic: fuel+park adds them, and this is the one place on the card +
is not a space. Encode the rest the same way. A full stop inside a number is
still a full stop: 4%2E5.

The colons that separate the fields of an f, i, r, c, s, t or u
stay as they are. A colon inside wording or a label is %3A, and once it is,
it can go anywhere: t=Verdict:n%3E0:Ship%3A+today reads back as "Ship: today".

The link stays under 2000 characters. To get there, shorten wording and remove
repetition first, then remove the least useful material. Keep every input and
intermediate result a remaining formula needs, keep the whole frame, and
never cut a sentence off.

BEFORE YOU REPLY

Change an input or choice in your head: the results follow it, the units
still make sense, and h and v are still true. Set an input to zero and
push a value across any target: every result is still usable.

Read the finished link once: it contains no bare *, (, ), < or >
anywhere, because each of those is always written encoded.

Reply with the URL and nothing else. No preamble, no code fence, no
explanation.
